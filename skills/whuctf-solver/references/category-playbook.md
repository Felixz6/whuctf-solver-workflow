# 分类战术

按题目的实际瓶颈选路线，不按扩展名下结论。文件类型提示来自 `triage` 的 `category_hint`，只帮助起手；单题分类以题面和代码为准。

备战时的默认顺序写在 `prep/whuctf-profile.json` 的 `priority`，当前是 reverse、web、crypto、pwn、misc、other。调整排期时改这份配置即可。下面各节的技术步骤不随这个顺序变化。

## Reverse

`file` / `xxd` / `strings` 看格式，再用 LIEF 或对应的 ELF/PE 解析看结构，然后用 radare2 看函数和交叉引用。沿输入到比较的控制流和数据流恢复算法，写求解器，再送回原逻辑校验。无关函数和整份反汇编不要倒进记录。

先记下真实格式、CPU、位数、端序、是否 PIE、是否加壳、入口、导入和资源。异常处理、TLS 回调、线程、JNI 和 GPU 代码里都可能藏着有效路径。

分清 `transform(input) == target` 和 `transform(target) == input`。TEA、XTEA、XXTEA 要看更新式和轮次，只看到 delta 不能认定算法。逐操作截断和带符号比较按目标 CPU 的语义解释。

虚拟机先恢复取指单位、指令长度、操作数、PC 如何推进、栈方向、寄存器和内存别名，以及溢出或异常。opcode 表恢复之后再 trace，不要把字节直接当本机机器码。

用 Z3 时写明 8/32/64 位 BitVec，逻辑右移用 `LShR`，带符号和无符号比较显式选择。检查模型是否唯一，或把全部候选都验证一遍，并设置超时，方便回头查约束。

Unicorn 只模拟已经识别的函数或代码段，映射栈、数据、返回地址和调用约定，导入调用用显式 hook。它模拟 CPU，不会自动提供操作系统的 syscall 语义。

angr 先加上真实的输入长度和格式约束，标出 find/avoid 地址，处理 PIE 的 `rebased_addr`。未约束就填零，或随意 hook，都不能当作解题证明。模型要送回真实逻辑复核。

Android 同时追 DEX 和 JNI。`RegisterNatives`、资源、签名或设备信息、Java 字符串和 native 缓冲区的转换要串起来。Python 字节码先匹配 pyc 版本。WASM 看导出、线性内存和字符串编码。

## Web

先保留一组正常请求和响应，再看路由和源代码，标出数据流和信任边界，找到最小漏洞原语，最后串到 flag。优先追题目自己的差分面。自定义 cookie 或 JWT、模板、文件接口、URL 解析、上传和解压、反序列化、原型链、bot 调用，各找对应入口。

保留正常请求和 payload 的原始请求、响应、状态码和关键字段。CVE 必须同时对上真实版本和触发条件；库名出现不等于漏洞成立。平台功能和题目实例分开记。

## Crypto

先给参数和可查询的 oracle 归类。RSA 检查 gcd、小 e、共模、近素数、相关消息和泄漏。对称算法检查 IV 或 nonce 复用、工作模式和认证。随机数先区分 Python、C 和 V8 的实现。

只有 HNP、小误差或部分泄漏才构造格。写出模方程、未知量的界、basis 的每一行、尺度，以及解向量的含义，再代回原式验证。fpylll 不能代替 Sage 的有限域和其他代数功能。

## Pwn

先确认 ELF、ABI 和保护，再确认漏洞与输入约束，做成可重复的原语，然后处理泄漏和地址，最后写利用。远程 libc 和 ld 以附件为准，不用本机版本猜测。现代 glibc 的 safe-linking、hook 移除、FILE 和 vtable 检查必须对上版本，不用过时的堆技巧冒充当前解法。

进程调试、seccomp、ptrace 和 libc 行为要在与题目一致的环境里验证。主机上的静态分析或 payload 生成不能代替目标环境的运行结果。

## Misc 与其他

压缩包、图片、PCAP 和音频按 magic 识别，不按后缀。先看元数据、结构和显著异常，再决定是否走字符编码、LSB 或通道、数据流、频谱。解压时留下原包并检查路径。jail 逐行追约束，把语言本身的语义和额外黑名单分开。

PCAP 先按协议和会话重组，再取应用数据。图片和音频保留每一层产物与提取参数。需要取证、OSINT 或 AI/ML 专题时，加载对应的现有技能。
